# Hiwonder's original firmware for the ROS Robot Controller V1.2

**Credit: everything in this folder was written and published by [Hiwonder](https://www.hiwonder.com/) (Shenzhen Hiwonder Technology Co., Ltd.) and the third-party projects listed below. It is not our work.** We include it unmodified so that anyone can rebuild, check or restore the firmware of the board on our robot without looking for it elsewhere. Our own changes are kept separately, as a patch, in [`../hiwonder_pos-v8/`](../hiwonder_pos-v8).

Source: Hiwonder's [ROS Robot Controller documentation and downloads](https://wiki.hiwonder.com/projects/ROS-Robot-Control-Board/en/latest/) · [product page](https://hiwonder.com/products/ros-robot-control).

## Contents

| Path | What it is |
|---|---|
| [`RosRobotControllerM4-armclang/`](RosRobotControllerM4-armclang) | Hiwonder's official FreeRTOS firmware project for the board (STM32F407VET6), version V1.2, exactly as Hiwonder distributes it (Keil MDK project in `MDK-ARM/`, STM32CubeMX file `RosRobotControllerM4.ioc`). Hiwonder's comments are in Chinese. |
| [`recovery/RosRobotControllerM4_factory_generic.hex`](recovery) | Hiwonder's factory firmware image (generic) |
| [`recovery/RosRobotControllerM4_Ackermann_12V.hex`](recovery) | Hiwonder's firmware image for Ackermann chassis at 12 V |
| [`recovery/SHA256SUMS`](recovery/SHA256SUMS) | Checksums of both images |

Hiwonder's project folder keeps its own `.gitignore`, so Keil's per-user files (`MDK-ARM/RTE/`, `MDK-ARM/DebugConfig/`, `*.uvguix.*`, `.mxproject`) are not tracked in Git. They are generated by Keil and not needed for the GCC build.

## How we use it

- **Our firmware `pos-v8`** = this project + [`../hiwonder_pos-v8/extended_m1.patch`](../hiwonder_pos-v8/extended_m1.patch) (12 files changed). The build steps are in [`../hiwonder_pos-v8/README.md`](../hiwonder_pos-v8/README.md#build-it-from-source).
- **Going back to the factory firmware:** flash one of the `recovery/` images with an ST-LINK/V2 on header H1, the same way as `pos-v8` ([flashing steps](../hiwonder_pos-v8/README.md#flash-it)). Our robot programs refuse to run on these images, because they do not answer the `MOTOR_EXT` command.
